# Архив сохранений — 0.35.0 / code50

Исправление подтверждённого блокера 0.34.1: нативная запись одного JSON переставала помещаться в 4 MiB при открытии 55-го большого дэйлика. Старые поля не удаляются, лимит AtomicFile не повышен. Исторический красный результат остаётся в PRODUCTION_READINESS_0341.md.

## Формат и граница подтверждения

Логическая GameSave schema2 и существующий строгий decodeSave остаются прежними. До 512 KiB сохраняется прежний JSON по `arrows.progress.v1`. Большой профиль переводится в физический `arrows-progress-archive`, version1. По прежнему ключу хранится только маленький корневой указатель; содержимое — отдельные неизменяемые блоки `arrows.archive.<sha256>`.

Геометрия embedded уровня отделена от изменяемого состояния попытки. Индексы дэйликов разбиты по годам/месяцам, текст — на части; каждый блок ограничен 128 KiB, проверяется SHA-256 при чтении и точным readback после записи. Порядок дат из исходного сейва сохраняется отдельно. Заголовок также разбивается на части: рост receipts/истории/прав не возвращает прежний лимит одного документа.

Порядок записи: подготовить и проверить все новые блоки → заменить один корневой указатель → проверить его readback → опубликовать состояние в ProgressStore/разрешить acknowledgement награды. Эффект и dedup ledger принадлежат одному корню. Ни сборка мусора, ни анимация не подтверждают результат. При потерянном ответе чтение устанавливает действующий корень; при недоступном подтверждении мутации блокируются до recovery.

Миграция происходит при загрузке до готовности игры и обработки наград. До публикации нового корня старый JSON остаётся действующим. Ошибка миграции не создаёт новый профиль. Пропавший/повреждённый блок приводит к существующему экрану восстановления, не к тихому сбросу. Совместимость — обновление старых сборок к 0.35; откат старого приложения после миграции не поддерживается.

## Адаптеры и стоимость

Android использует прежнюю очередь IO и AtomicFile для каждого значения, с прежним пределом 4 MiB. Добавлен только список имён блоков для уборки. Браузер держит immutable блоки в IndexedDB, а корень/настройки — по существующим ключам localStorage. Успех IndexedDB означает завершённую транзакцию, а не только success отдельного put.

Мутации сериализуются через Web Locks, когда они доступны, с проверкой исходного корня перед записью; внутри одного процесса есть резервная очередь. Устаревший writer не может затереть более свежую миграцию/награду. Без Web Locks не обещается межвкладочная атомарность, браузерная фоновая уборка отключена. Android-приложение имеет одного владельца игрового сейва.

После commit допускается ограниченная уборка до 16 недостижимых блоков за проход под тем же lock, только для текущего корня. Ошибка удаления не отменяет commit. Блоки не считаются существующими только потому, что когда-то были подготовлены: повторная запись после сбоя проверяет их заново. Геометрия заморожена и разделяется; copy-on-write копирует только изменяемую часть затронутой попытки. Холодное чтение пока восстанавливает и валидирует весь логический архив: измерения Node не доказывают скорость телефона, предел свободного диска не исчезает.

## Сохранённые правила

Без изменений: опубликованные уровни и генераторы, attempt/content IDs, удалённые и ошибочные стрелки, жизни, flawless, камера, cups/design bindings, lifetime free continue, Hint/schema1 и schema2 meanings, pending requests/earned rights, резервные награды, рекламный ритм, SDK/kit pins, интерфейс, звук и переводы. Поздняя награда не заменяет действующую помощь.

## Проверки

Факты и точные итоговые статусы — в evidence/archive-storage-035/ACCEPTANCE.md. Автоматический capacity gate строит настоящий профиль из 54 больших дат, мигрирует его, открывает 55-ю и далее 730 реальных дат через ProgressStore.openDaily. Отдельно создаётся явно авторский профиль с 727 завершёнными/3 частичными полями, историей ошибок/камерой, кубками и потраченным lifetime gift; он проходит прежний decoder. Независимый grid oracle даёт законную последовательность для fixture, а не доказательство человеческого прохождения/удовольствия.

Новые тесты проверяют прерывание до блока/корня, неверные байты, потерянный ответ, недоступный readback, повтор награды, stale writer, pending request, поздний legacy Hint, сбой уборки. Два старых fault-injection observer теперь включают read failure после фактически принятой записи: новый preflight читает корень до начала записи, а потерянный ответ должен воспроизводиться на прежней post-write границе.

Нативный force-stop/обновление установленной APK, скорость холодного старта/хода на физическом телефоне остаются отдельным NOT RUN, пока не проверены на устройстве. Live AppMetrica/реклама/деньги/production signer остаются отдельными воротами.
