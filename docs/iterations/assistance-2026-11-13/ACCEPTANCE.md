# Приёмка пакета «Стрелки»

Это перечень проверяемых результатов будущей реализации. На момент передачи ТЗ новые функции не реализованы; строки не являются отчётом о пройденных тестах. Офлайн-доказательства из `proof/` имеют отдельный статус.

## Как использовать

- Для первой поставки обязательны BASE, C, A-01...A-15, применимые FEEL и DELIVERY. Сценарии A3/A4/B1 проверяются при соответствующей поставке; B2/B3 остаются лабораторными и не блокируют первую APK.
- Одна строка не требует отдельного test file. Переиспользовать существующий runner, fixtures и способы захвата. Автоматизировать рискованные правила, миграции, receipts и lifecycle; не писать хрупкие тесты на каждый оттенок/коэффициент анимации.
- Для каждого сценария записать `PASS / FAIL / NOT RUN / NOT APPLICABLE`, точный commit/build, условия и ссылку на свидетельство. `NOT RUN` не превращается в PASS из-за зелёного общего CI.
- У визуальных проверок указать browser/Canvas/WebGL/emulator/physical Android, viewport/DPR/zoom/theme. У аудио - реальный выход, у haptics - устройство или открытый статус.
- Если внешняя проверка недоступна, завершить доступную работу и выдать тестовую сборку с точным списком ограничений. Не останавливать всю поставку из-за отсутствия кабинета или телефона.

Модуль F проверяет фактическое совпадение цвета/обещания/вылета, ранний ввод, reduced motion, текущую камеру и отсутствие лишних кадров на спокойном поле.

Ниже поведенческие критерии. Уровень проверки должен соответствовать утверждению: domain/save тест не доказывает изображение; кадры не доказывают native тактильность; браузерное воспроизведение не доказывает APK/телефон.

## Минимальный набор демонстраций первой поставки

1. Малое поле: A1 до/после, сохранённая цель, ранний ввод во время перекраски.
2. c40: каскад root22+23/24/27; отдельно вариант с error-marks23/24 и корректным различением native/bonus.
3. c20 или c120: панорамирование/масштаб во время эффектов, плотность, мягкие края и отсутствие скачка камеры.
4. Отмена ожидания рекламы и поздний onLoaded; earned, фон/возврат; неиспользованное право после restart.
5. Совпадение конца каскада с победой: один финал, тишина/idle после завершения.

Для следующих поставок добавить ручной маршрут c20-9→12→15 с паузой/skip, A4 со свободным и занятым слотом, B1 с оставшимися на поле стрелками. Технически seeded QA допустим для воспроизведения, но не подписывается как естественное прохождение игрока.
