## Вердикт

**Предлагаемый следующий шаг обоснован:** закрыть конкретные пробелы измерения существующего пакета и два небольших незавершённых UX-требования; затем проверить текущую APK с человеком и настоящим test SDK. Этот аудит не даёт основания сейчас добавлять новый director, новую рекламную частоту или платный продукт.

Это завершение уже выданного C/A1-пакета. Большая часть помощи, сохранения прав, вариантов A2/A3/A4 и исходов после continue уже присутствует; повторное «ТЗ на всё с нуля» было бы ошибкой.

## Ограничения исправлений

- Для restart сохранить корреляцию исходного offer episode до открытия подтверждения, затем записать выбор после подтверждения. Не превращать само открытие диалога или Cancel в подтверждённый restart; не увеличивать offer count повторными `sync()`.
- Для потерь сделать ограниченный диагностический export/snapshot со счётчиками. Не обещать exactly-once доставку и не строить большой telemetry backend ради одного 32-RPC бюджета. Привязать метрики к контексту сборки/сеанса, различать invalid-schema и overload по возможности.
- Для QA добавить явное окружение/режим рекламы в идентичность потока и проверять его в денежном расчёте. Сохранить analytics OFF у пользовательской `.playtest`; проверку кабинета выполнять отдельно. Не менять live SDK IDs/частоту в рамках этих исправлений.
- Backoff: один актуальный refresh/снятие устаревшей надписи после срока при foreground-спросе, без fake ready и request storm.
- A1: видимость только третий приоритет после реальной пользы, пересчёт только не принятого offer по существенному изменению камеры. Earned target и зафиксированное обещание не перемещать вслед за камерой.

## Рекламные выводы

Пауза после rewarded уже имеется и распространяется на следующий interstitial: 150 активных секунд плюс две новые уникальные победы. Она не ограничивает всю добровольную rewarded-активность единым таймером. Первый межуровневый показ возможен после шестой победы (`wins >= 6`).

Полная отсрочка после failed/no-fill/cancel — текущая намеренная политика. Её изменение уже выделено как CADENCE-LAB и не входит в исправление найденных дефектов. Отсутствие новой returnee grace само по себе также не доказывает необходимость менять ритм.

## Проверка переносимости

`ads-readiness-probe.mjs` теперь принимает путь репозитория первым аргументом, optional JSON output вторым; по умолчанию пишет ADS_READINESS_PROBE.json рядом с самим скриптом. Проверяет точный HEAD и отсутствие tracked diff в двух исполняемых исходниках. Повторный запуск прошёл, результат unchanged. Tracked source не изменён.

```bash
node ads-readiness-probe.mjs /path/to/arrows
```

Нужны установленные зависимости checkout и Node 24+ с поддержкой TypeScript. Это исполнение настоящих application modules с контролируемыми transport/time, а не реальный Android SDK.
