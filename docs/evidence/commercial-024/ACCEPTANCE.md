## Measurement limits and next separate gate

SDK accepted is NOT dashboard delivery; a saved help outcome is NOT a durable analytics outbox. An uncertain accepted write may restore the terminal M1 state without having delivered its event; stable IDs and export joins avoid inventing exactly-once delivery. Explicit Home closes the observation (same limited-exit policy as continue); returning later does not reopen that observation. New-help grant/claim closes it even if the next helper is not executed. Continue/A4 use their existing outcome stream rather than another M1 observer.

Health is cumulative within one JS transport instance and rate-limited; sequence dedup avoids summing repeated cumulative totals. A missing health row is null/unknown, not zero losses; both callback and money rows can be absent. Coverage counts only observed export, not true total SDK impressions. F5 changes legacy/no-envelope rows to unknown instead of retroactively calling them live; existing assignment identity is not recreated for analysis. The synthetic before/after0.25RUB fixture is a parser/selection test, not an SDK earning or income estimate. liveVerified remains false.

Pending separately: named-device install/update, native test-ad readiness/earned/background/process restore, physical sound/haptics/frame pacing; analytics-enabled QA build with separate debug project→device→cabinet/export, health visibility/provenance/ILRD reconciliation and mature7d assigned-install denominator.
