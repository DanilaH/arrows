# Независимый UI / UX / feel аудит — 14 ноября 2026

**Вывод:** у 0.24.0 уже есть последовательный минималистичный интерфейс и содержательный отклик поля. Оснований переделывать шрифт, графику стрелок, плотность всего UI или добавлять новые эффекты не обнаружено. Главный подтверждённый недостаток — анимация DOM-кнопок иногда мешает самому нажатию. Далее по пользе идут непрерывность окон, читаемость закрытых разделов и обзор полученной помощи. Это несколько локальных исправлений, а не новый UI-фреймворк.

Это инженерный и визуальный аудит исполняемой игры. Он не заменяет человеческий плейтест, оценку звука через динамик телефона или измерение кадров на Android. Приложение в рамках аудита **не изменялось**; ниже предложения, не список уже исправленных проблем.

## Источник и объём

- Arrows: рабочий `main` **342646314b601a3684efbbeea93d3441950aa657**, актуальный application source **84a1a5d37ebd761054d6aefcaccb3505e5f27b3a**, **0.24.0 / code36**. Более свежая работа сохранена; отката к исследовательской базе не было.
- Прочитаны актуальные HANDOFF, AGENTS, решения и действующие документы Minimal UI, UX Review, Phone Feel V2, Soft Board Edges, Seamless Entry, Assistance Iteration; проверены реализация, тесты и предыдущие acceptance-отчёты.
- Проверялась **неизменённая production dist**, собранная из текущего кода, в headless Chromium. Полноценный интерактивный запуск через облачный Chrome не состоялся: его отдельная среда не видит локальный preview. Браузерные проверки запускались в изолированном окружении проекта с собственным preview.
- 76 снятых состояний: Home, новые игроки/обучение, Settings, две темы, RU/EN, Collection/раскрытие медалей/список кубков, шестистрочный календарь, выбранная дата, полученный кубок, ежедневная игра/её результат, Restart. Дополнительно: A1/A2/A3, ожидание и отмена награды, A4 с пустой/занятой помощью, победы c09/c19/c120, B1, прерывание окон, реальные mouse/touch нажатия.
- Геометрии: **390×844, 320×568, 568×320, 800×1280**; отдельный **320×640 с синтетическим CSS text 150%**. Последний — stress test, **не Android system font scale**. Прогресс поздних уровней и заработанный августовский кубок явно подготовлены QA, не получены человеком.
- Rewarded-сценарии использовали существующий контролируемый native transport поверх настоящего приложения/writer. Это **не видео рекламного SDK** и не денежная проверка.

**Ограничение нового QA-helper:** его исходные corner-probes находятся в3px от угла DOM-прямоугольника. У наших намеренно округлых кнопок это точка вне самой формы; helper возвращает `occluded-or-not-interactive` даже без перекрытия. Сырые результаты сохранены. Отдельно проверены9 допустимых внутренних/срединных точек и реальные координатные нажатия. Во всех12 состояниях Home/loss/c120 result на4 профилях критичные действия доступны; первый целевой tap дал ожидаемый переход/восстановление жизней. Это документированная граница axis-aligned helper, не12 багов приложения. Для регрессий нужна проверка реальной формы, а не механическое переименование FAIL в PASS.
